## Overview

`FireboltEngineDefaults` is an optional namespaced resource that holds ambient engine settings for a namespace: a pod-template fragment plus defaults for `storage` and `customEngineConfig`. Every Firebolt Engine in the same namespace merges it. Engines do not reference the object by name.

Values resolve **Engine > Defaults > EngineClass > Firebolt Operator default**. SKU-shaped settings (`rollout`, `autoStop`, `uiSidecar`, drain checks) stay on `FireboltEngineClass`.

v1 admits one `FireboltEngineDefaults` per namespace. The conventional name is `firebolt`. Creating a second object in the same namespace is rejected.

Set `FireboltEngine.spec.requireDefaults: true` when an Engine must not become Ready until Defaults exists and is Ready. A present but unready object, or more than one object in the namespace, fails closed for every Engine even when `requireDefaults` is unset.

The Firebolt Operator validates `spec.template` with the same operator-owned-path rules as `FireboltEngineClass`, and reports `Ready` on the object. Deleting the object is refused while any Firebolt Engine exists in the namespace. A Defaults edit that changes the pod template, storage, or engine config rolls a new blue-green generation.

For the allowlist of user-settable and Firebolt Operator-owned template fields, see the [FireboltEngineDefaults CRD reference](../crd-reference/fireboltenginedefaults-crd-reference).

## Inspecting status

```bash
kubectl get firengd -n firebolt
```

```
NAME       BOUND   READY   AGE
firebolt   3       True    24h
```

`BOUND` is the number of Firebolt Engines in the namespace. Defaults is ambient, so every engine in the namespace counts.

## Example

```yaml
apiVersion: compute.firebolt.io/v1alpha1
kind: FireboltEngineDefaults
metadata:
  name: firebolt
  namespace: firebolt
spec:
  template:
    spec:
      serviceAccountName: firebolt-engine
      containers:
        - name: engine
          envFrom:
            - secretRef:
                name: engine-object-store
  storage:
    emptyDir: {}
  customEngineConfig:
    storage:
      managed_table_storage: s3
      managed_table_bucket_name: my-bucket
```

Apply the manifest:

```bash
kubectl apply --server-side -f firebolt-engine-defaults.yaml
```
