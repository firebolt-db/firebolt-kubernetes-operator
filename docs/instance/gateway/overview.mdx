## Overview

The Firebolt Operator Gateway uses [Envoy Proxy](https://www.envoyproxy.io/) for client traffic and a local agent for request admission. Lua validates the Engine selector; the agent supplies an immutable generation destination through Envoy's `ext_proc` filter. Envoy discovers ready Pods for that destination through its dynamic forward proxy.

- [Gateway query routing](./gateway-query-routing) describes admission, retries, and withdrawal before Engine shutdown.
- [Gateway sizing](./gateway-sizing) describes replica count, memory limits, and the 2 MiB retry-buffer constraint.

## Connect to engines

### Instance gateway

The Instance Gateway is the supported entry point for Engine queries. The Envoy proxy routes requests based on the target engine name and handles retries during blue-green transitions. Pass the engine with the `X-Firebolt-Engine` header (raw HTTP clients) or the `engine` query parameter (the bundled `firebolt` CLI).

```text
POST http://<instance-name>-gateway.<namespace>.svc.cluster.local/
Headers:
  X-Firebolt-Engine: my-engine
  Content-Type: text/plain
Body: <SQL>
```

With the Firebolt CLI from an engine pod:

```bash
firebolt client \
  --endpoint http://<instance-name>-gateway \
  --insecure \
  --set engine=my-engine \
  -c "SELECT 42" \
  --no-interactive
```

### Configuration

The Envoy ConfigMap (`<instance>-gateway-config`) depends on Instance configuration. Engine create, delete, scale, and rollout events update a separate routing coordination ConfigMap instead of restarting the Gateway fleet.

The local agent is required for all Engine query traffic. It must register its Pod UID and process identity with the Firebolt Operator before becoming ready or admitting requests. The agent's `/readyz` probe checks that registration. An unavailable or unregistered agent cannot be bypassed by Envoy.

### Gateway custom service account

By default, the Firebolt Operator creates the `<instance>-gateway` ServiceAccount. It binds a namespaced Role granting the agent `get`, `list`, and `watch` on EndpointSlices and on its single coordination ConfigMap. The ConfigMap grant is restricted by resource name. Only the Firebolt Operator writes routing assignments and session records.

Set `spec.gateway.template.spec.serviceAccountName` to use an existing ServiceAccount. You create that account; the Firebolt Operator leaves the account itself untouched and binds the same read-only Role to it. A custom identity does not disable admission or wake-up.

The Gateway Pod always sets `automountServiceAccountToken: false`. A rotating token is projected only into the agent, so Envoy does not hold a Kubernetes credential. The Firebolt Operator overrides a template's `automountServiceAccountToken: true` value to preserve this isolation.

A missing custom ServiceAccount prevents the Gateway Pod from starting. Create it in the Instance namespace before selecting it.

## Rolling update parameters

### Gateway deployment

| Parameter | Value | Rationale |
|-----------|-------|-----------|
| `maxSurge` | `25%` | Standard Kubernetes default for gradual rollout |
| `maxUnavailable` | `0` | Maintain full capacity during image switches |
| PodDisruptionBudget | `maxUnavailable: 1` | Allow voluntary disruptions while maintaining availability |

### Gateway replacement

During a planned Gateway replacement, Envoy fails readiness and closes its query listener to new connections. Accepted requests can finish, including requests waiting for an Engine to wake. The agent runs as a Kubernetes native sidecar, so routing registration, request accounting, and wake handling remain active until Envoy and the other main containers have stopped. A Pod finalizer preserves evidence of Envoy termination until the Firebolt Operator has cleared its registered session. The metrics listener and local admin interface remain available during draining.

The default pod shutdown budget is 180 seconds. Set `spec.gateway.template.spec.terminationGracePeriodSeconds` to cover the remaining wake wait, query execution, and container shutdown:

```yaml
spec:
  gateway:
    template:
      spec:
        terminationGracePeriodSeconds: 180
```

The budget starts when Kubernetes begins terminating the pod. When it expires, Kubernetes forcibly terminates remaining containers, interrupting unfinished requests. Closing the query listener does not wait for external load balancers to observe the pod's removal; configure their draining behavior for your environment.
